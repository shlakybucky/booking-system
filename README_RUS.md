# Система Бронирования

Комплексная система бронирования мероприятий, построенная на NestJS, Prisma и PostgreSQL. Это приложение позволяет пользователям создавать мероприятия, управлять бронированиями и отслеживать метрики с интегрированным мониторингом с использованием Prometheus и Grafana.

## Описание

Система Бронирования — это RESTful API сервис, предназначенный для управления бронированием мероприятий. Он предоставляет функциональность для:

- Создания и управления мероприятиями с указанным количеством доступных мест
- Резервирования бронирований для пользователей на мероприятиях
- Отслеживания статистики и метрик бронирований
- Мониторинга производительности приложения с помощью Prometheus и Grafana
- Просмотра топовых мероприятий по количеству бронирований

Система обеспечивает целостность данных, предотвращая дублирование бронирований (пользователь может забронировать только один раз на мероприятие) и отслеживает все действия по бронированию с временными метками.

## Возможности

- **Управление мероприятиями**: создание, чтение и удаление мероприятий
- **Система бронирования**: резервирование мест для пользователей на мероприятиях с предотвращением конфликтов
- **Топ мероприятий**: запрос топ-10 наиболее забронированных мероприятий
- **Сбор метрик**: встроенные метрики Prometheus для мониторинга
- **Документация API**: документация Swagger/OpenAPI доступна по адресу `/api/docs`
- **Визуализация базы данных**: Prisma Studio для управления базой данных
- **Поддержка Docker**: полная контейнеризация с Docker Compose
- **Стек мониторинга**: интеграция Prometheus и Grafana

## Начало работы

### Вариант 1: Использование Docker (Рекомендуется)

Самый простой способ запустить приложение – использовать Docker Compose, который настраивает все сервисы, включая базу данных, приложение, Prometheus и Grafana.

#### 1. Создание файла окружения

Создайте файл `.env` в корневой директории:

```bash
# Конфигурация базы данных
DATABASE_URL="postgresql://postgres:postgres@postgres:5432/booking_db?schema=public"
DB_HOST=postgres
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=postgres
DB_NAME=booking_db

# Конфигурация приложения
APP_PORT=3000
STUDIO_PORT=5555

# Окружение Node
NODE_ENV=development
```

#### 2. Запуск сервисов

Используя Make (рекомендуется):

```bash
make up
```

Или используя Docker Compose напрямую:

```bash
docker-compose -f docker/docker-compose.yml --env-file .env up --build -d
```

#### 3. Проверка сервисов

Проверьте, что все сервисы запущены:

```bash
make ps
# или
docker-compose -f docker/docker-compose.yml ps
```

#### 4. Доступ к приложению

После запуска будут доступны следующие сервисы:

- **API**: http://localhost:3000
- **Документация Swagger**: http://localhost:3000/api/docs
- **Prisma Studio**: http://localhost:5555
- **Prometheus**: http://localhost:9090
- **Grafana**: http://localhost:3001 (admin/admin)

#### 5. Остановка сервисов

```bash
make down
# или
docker-compose -f docker/docker-compose.yml down -v
```

### Вариант 2: Локальная разработка

Если вы предпочитаете запускать приложение локально без Docker:

#### 1. Настройка PostgreSQL

Убедитесь, что PostgreSQL запущен, и создайте базу данных:

```sql
CREATE DATABASE booking_db;
```

#### 2. Настройка окружения

Создайте файл `.env`:

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/booking_db?schema=public"
APP_PORT=3000
NODE_ENV=development
```

#### 3. Генерация Prisma Client

```bash
yarn prisma:generate
```

#### 4. Запуск миграций

```bash
yarn prisma:migrate
```

#### 5. Заполнение базы данных

```bash
yarn prisma:seed
```

#### 6. Запуск приложения

Режим разработки (с горячей перезагрузкой):

```bash
yarn start:dev
```

Режим продакшена:

```bash
yarn build
yarn start:prod
```

### Эндпоинты мероприятий

#### Получить все мероприятия

```http
GET /api/events
```

**Ответ:**
```json
[
  {
    "id": 1,
    "name": "Coldplay World Tour 2025 — London",
    "totalSeats": 50000,
    "createdAt": "2025-01-01T00:00:00.000Z",
    "updatedAt": "2025-01-01T00:00:00.000Z"
  }
]
```

#### Получить мероприятие по ID

```http
GET /api/events/:id
```

**Параметры:**
- `id` (number): ID мероприятия

#### Получить топ-10 мероприятий

```http
GET /api/events/top?date=2025-01-01
```

**Параметры запроса:**
- `date` (string, опционально): Фильтр по дате (формат ISO)

**Ответ:**
```json
[
  {
    "name": "Coldplay World Tour 2025 — London",
    "totalCount": 150
  }
]
```

#### Создать мероприятие

```http
POST /api/events
Content-Type: application/json
```

**Тело запроса:**
```json
{
  "name": "Название нового мероприятия",
  "totalSeats": 1000
}
```

**Ответ:**
```json
{
  "id": 1,
  "name": "Название нового мероприятия",
  "totalSeats": 1000,
  "createdAt": "2025-01-01T00:00:00.000Z",
  "updatedAt": "2025-01-01T00:00:00.000Z"
}
```

#### Удалить мероприятие

```http
DELETE /api/events/:id
```

**Параметры:**
- `id` (number): ID мероприятия

### Эндпоинты бронирования

#### Зарезервировать бронирование

```http
POST /api/booking/reserve
Content-Type: application/json
```

**Тело запроса:**
```json
{
  "eventId": 1,
  "userId": 123
}
```

**Ответ (Успех - 201):**
```json
{
  "id": 1,
  "eventId": 1,
  "userId": 123,
  "createdAt": "2025-01-01T00:00:00.000Z"
}
```

**Ответ (Конфликт - 409):**
```json
{
  "statusCode": 409,
  "message": "Бронирование уже существует для этого пользователя и мероприятия"
}
```

#### Получить все бронирования

```http
GET /api/booking/all
```

**Ответ:**
```json
[
  {
    "id": 1,
    "eventId": 1,
    "userId": 123,
    "createdAt": "2025-01-01T00:00:00.000Z"
  }
]
```

#### Получить все бронирования с деталями пользователей

```http
GET /api/booking/all_with_users
```

**Ответ:**
```json
[
  {
    "id": 1,
    "eventId": 1,
    "userId": 123,
    "createdAt": "2025-01-01T00:00:00.000Z",
    "event": {
      "id": 1,
      "name": "Название мероприятия",
      "totalSeats": 1000
    }
  }
]
```

### Схема базы данных

Приложение использует две основные модели:

**Event (Мероприятие):**
- `id`: Уникальный идентификатор
- `name`: Название мероприятия
- `totalSeats`: Общее количество доступных мест
- `createdAt`: Временная метка создания
- `updatedAt`: Временная метка последнего обновления

**Booking (Бронирование):**
- `id`: Уникальный идентификатор
- `eventId`: Ссылка на мероприятие
- `userId`: Идентификатор пользователя
- `createdAt`: Временная метка бронирования

**Ограничения:**
- Уникальное ограничение на `(eventId, userId)` для предотвращения дублирования бронирований

## Решение проблем

### Порт уже используется

Если вы столкнулись с конфликтами портов:

```bash
# Проверить, что использует порт
lsof -i :3000
lsof -i :5555

# Завершить процесс или изменить порты в .env
```

### Проблемы с подключением к базе данных

1. Убедитесь, что PostgreSQL запущен
2. Проверьте правильность `DATABASE_URL` в `.env`
3. Проверьте учетные данные базы данных

### Проблемы с Docker

```bash
# Просмотр логов
make logs

# Перезапуск сервисов
make down
make up

# Очистка всего
docker-compose -f docker/docker-compose.yml down -v
```
